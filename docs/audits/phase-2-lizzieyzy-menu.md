# Phase 2 LizzieYzy Menu Check

- Date: 2026-11-21
- Status: Approved by the owner on 2026-11-21, with the Phase 2 plan. Its gaps are placed in milestones there, its questions became decisions P8 to P12 with the plan's defaults, and P2-X1 to P2-X5 and P2-W1 to P2-W3 are applied to the charter
- Phase: Phase 2, "Review core" (charter section 8). This check opens the phase. Its result feeds the [Phase 2 plan](../superpowers/plans/2026-11-21-phase-2-roadmap.md), section 9.
- Charter: [section 7](../superpowers/specs/2026-11-19-aji-project-charter-design.md) requires this check at the start of each phase. Previous check: [Phase 1](phase-1-lizzieyzy-menu.md). Interface design: [aji-ui-design](../superpowers/specs/2026-11-19-aji-ui-design.md). Deferred work: [Phase 1 deferred items](../backlog/phase-1-deferred.md).
- Markers follow the charter. Everything that changes scope is **[Proposed]**, except the three removals the owner decided on 2026-11-21 (P2-X1 to P2-X3), which this check records. This document edits neither the charter nor any plan.

Chinese appears only where it quotes a LizzieYzy label to identify an entry, as charter section 7 allows, and almost always in the second column of the tables. No LizzieYzy code was copied. LizzieYzy is GPL-3.0 and is used as a feature reference only.

## 1. Result

- **Three charter rows leave Phase 2 for 7.10**, by the maintainer's decision of 2026-11-21: the policy heatmap (first instinct) and post-search heatmap, raw network mode (no search), and pasting and copying a game through the clipboard. Eighteen LizzieYzy keys hang on them (P2-X1 to P2-X3). They supersede Phase 1 rows F6 and C13 (its heatmap and raw-network parts) and charter 7.2 "Paste a game…" and 7.3 "Policy heatmap…" and "Raw network mode…". Copying a *screenshot* to the clipboard is not affected.
- **The charter still says blunder bars shipped in Phase 1. They did not.** The owner had them removed after the first M7 build (M7 design 13.2; interface design 4.2, "There are no mistake bars", Decided). LizzieYzy's bar and threshold options are therefore Covered differently (WG3). The draft Phase 2 plan, however, puts "blunder bars, the thresholds that set them" into its M2. They cannot both stand (P2-Q3). Charter 7.3 needs its wording fixed either way (P2-W1).
- **Two Phase 2 rows sit awkwardly with the interface design.** The owner kept the whole Phase 2 list (charter D3), so the question is how, not whether. It needs an answer before the P2-M3 design:
  - **Try-out (试下).** Charter 7.2 lists try-out mode. Interface design 4.1 says "no 'try a move' button", and section 6 says playing a move always makes a variation (P2-Q1).
  - **Markup.** Charter 7.2 lists markup and freehand drawing. Interface design 6 has "no 'mark a point without playing' feature for now", which is Proposed, not Decided (P2-Q2).
- **The candidate list window was misfiled in the Phase 1 check.** Its 21 `AnalysisFrame` entries were grouped with Hawk-eye under Phase 5. They are LizzieYzy's independent candidate list (选点列表), which is 7.3's Phase 2 "Candidate list panel" (CA1).
- **LizzieYzy has a mistake list in the main window**, not only in Hawk-eye: the comment pane can switch to a table of each side's biggest swings, with a threshold and an "only after this move" filter. Click a row to jump to it. It fits P2-M2 once whole-game analysis exists (P2-G7).
- **Imported LizzieYzy analysis is approximate.** The `LZ` property stores visit counts in abbreviated form (such as `1.2k`). LizzieYzy's reader also converts each stored win rate (`100 − x`), so the importer must confirm whose side the figure is from. The cache must mark imported results so that fresh analysis replaces them (WA10, K4).
- **LizzieYzy often runs a second engine where Aji needs only one.** It has a separate estimate engine (a second KataGo, or Zen), a separate flash-analysis engine with its own command and rules, and "fast switch", which keeps the old engine loaded. Aji's single analysis engine (charter 6.2) folds each into one feature (EN5, EN8, WA4, OW3, OW4).
- **Counts:** 101 numbered rows in sections 3.1 to 3.10, plus 22 re-check rows in 3.11. By first disposition: 52 Covered, 18 Covered differently, 5 Covered in part, 10 Gap, 6 Later, 4 7.10+, 2 7.10 and 4 Not a feature; some rows split between two. The proposals are 12 Phase 2 gaps (P2-G1 to P2-G12), 5 questions for the owner (P2-Q1 to P2-Q5), 5 additions to 7.10 (P2-X1 to P2-X5), 3 charter wording fixes (P2-W1 to P2-W3) and 4 later-phase items (P2-L1 to P2-L4). Of the Phase 1 later-phase items, L1, L3, L4, L5, L7 and L8 become Phase 2 gaps, and the draft plan already takes most of them; L2 and L6 carry over.

### 2.4 Dispositions

The vocabulary is the Phase 1 check's, with one change. The Phase 2 plan is still a draft, so **Covered** means that a Phase 2 charter row exists and a milestone of that draft is named.

| Disposition | Meaning |
|---|---|
| **Covered** | A charter row delivers it. The milestone named is a proposal. "Covered · P1" means it already shipped in v0.1.0 |
| **Covered differently** | The charter row is met by a different design, cited in the notes |
| **Covered in part** | Some of it shipped or is planned; the rest is named |
| **Later** | A charter row in a later phase takes it |
| **7.10** | An existing bullet in charter 7.10 covers it |
| **7.10+** | Not done on purpose, but 7.10 does not say so yet. A new bullet is proposed in section 4 |
| **Gap** | Not in charter section 7. A home is proposed in section 4 |
| **Not a feature** | Exists only because of LizzieYzy's Java Swing implementation, or is a dead string |

**Milestones.** P2-M1 to P2-M4 are the owner's four Phase 2 milestones of 2026-11-21, which are M1 to M4 of the draft plan. Where the draft places an item differently from the owner's first outline, this check follows the draft:

- **P2-M1:** the panel system and presets, board and stone styles, small screens and touch, the keymap, interface scale, the perspective and score options, screenshots, always on top.
- **P2-M2:** the persisted cache, whole-game analysis, the candidate list, quality marks, the next-move hint, ownership, the estimate and final scoring, LizzieYzy import and save with analysis.
- **P2-M3:** game editing (variations, undo, comments, markup, setup, try-out, transforms, game information and rules), coordinates and move numbers, click to jump, auto-replay, save options, analysis of all branches.
- **P2-M4:** engine profiles and the console, the sub-board, the shortcut editor and LizzieYzy preset, sessions, visits along the hovered line, and acceptance.

Plain M2 to M8 refer to Phase 1's milestones. Row IDs are new for this check (EN, BD, ED, SV, NV, CA, OW, WG, WA, UI), so they do not collide with Phase 1's E, F, N, C, H, A and I rows.
