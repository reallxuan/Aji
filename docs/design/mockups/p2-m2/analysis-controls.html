The same made-up 247-move game as the M7 trend-graph mockup, open at move 130. Before the job starts, the user has looked at moves 0–95, 111–130 and 238–247 by stepping through them, so those already have results (the graph's gaps are the rest).
  • Round 1 decisions: start from the menus only (1B); progress as a strip under the graph (3A); no "·" in any interface text, and the captures line now reads 提子 黑 3 白 5.
  • New in this round: 波动时加强. Once every move has a result, the moves where the win rate swings sharply get a second, deeper search (sections 2 and 4).
  • One engine. The job uses the same KataGo as the board. Whatever position the user is on is always searched first. Results are cached, so a position that already has enough visits is skipped, and after quitting the job carries on where it stopped.

2 开始前：分析全局…

分析全局… opens a panel that drops from the game title, the way the rules chip opens its panel today. It holds the three choices the roadmap asks for (audit P2-G2), plus 波动时加强. Every choice is remembered for the next game. 每手计算量 is the job's own budget, separate from the board's 每步计算量上限 (which can be 不限). Positions that already have this many visits are counted and skipped. 波动时加强: after the first pass, wherever the win rate changes by more than the threshold from one move to the next, both positions are searched again, up to the larger budget. A swing measured at 500 visits is often noise; at 3000 it is usually real, and the graph and candidates there become trustworthy. My calls: 500 visits per move; boosting on, at a 10% swing, up to 3000 visits; Return starts.

6 设置

Settings → Analysis gains two rows. 打开棋谱时分析全局 is off by default (P4). When it's on, the job starts with the remembered choices whenever a game opens. 分析缓存 shows how much space the cache uses, its size limit (P5) and a 清除 button. The job's own choices live in its panel (section 2), not here.
